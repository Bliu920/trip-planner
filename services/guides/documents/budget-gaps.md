# Resolve missing prices

The attached budgetCheck is a mechanical coverage report. pending lists entry IDs that still need action. A valid proposal is staged, not saved. readyToCommit only means the mechanical check permits saving. A completed budget should normally have numeric estimates for every included cost.

researchWeb returns readable evidence and registers retrieved URLs with the workspace. If its report contains usable prices, propose those prices and URLs directly. No separate pricing-evidence tool is needed.

For each pending cost, use the following bounded recovery:

- If searchAvailable is true, make a targeted researchWeb follow-up after this check. Request the relevant official fare, ticket, menu or room rate, with numeric facts, unit, conditions and direct source URL. If an exact quote is unavailable, search comparable options in the same city and season with similar quality and units. Do not repeat an exact-date query when a representative rate would support an estimate. Batch related gaps in one call when useful. A URL list alone contains no price evidence.
- Read actual numeric amounts and conditions. Record useful price facts immediately in createBudget/editBudget: amount or range, quantity, unit, applicability, source URL, retrieval time and concise evidence detail. Preserve unrelated entries. Do this before unrelated document work. Never infer a price just because a URL was returned.
- Missing dates generally allow an indicative estimate. Missing party size allows per-person scope. Neither automatically makes every cost unknown. For variable rates, research representative options and derive a reasonable low/high range with clearly labeled assumptions. Save it as estimated with the numeric anchors in source detail and the extrapolation in assumptions. A comparable price need not be an exact quote for the selected item. A budget limit is not evidence of a cost.
- After a targeted follow-up covering direct and comparable prices, stop repeating unsuccessful searches and use the researched anchors to estimate. Only when no defensible numeric evidence can be obtained or reused, call resolveBudgetGaps with its pending ID and a concrete explanation of what was checked, what was unavailable, and what would permit a price. Use not_found only when both direct and comparable research failed; missing_details only when specific missing user information prevents even a defensible indicative estimate. Include any useful actual retrieved source on the unknown entry before resolving it. Do not invent sources or claim a page was read when only its URL was returned.
- If searchAvailable is false, use search_unavailable and say online research is disabled. Existing direct or comparable document evidence may still support estimates; use it before declaring a cost unpriced. Enabled search cannot be dismissed as unavailable merely because the first query was unhelpful.

resolveBudgetGaps appends the explanation to the staged entry's assumptions. Do not re-propose an older copy that erases it. Changing the cost, estimate scope or plan reopens its check. Once pending is empty, review numeric coverage and commit. Resolved unknowns preserve incomplete work; they do not make the budget complete. Report any such limitation explicitly. Unknown amounts remain null and must be described as missing costs. A partial subtotal is not the complete trip total; an entirely unpriced budget is not an estimate. Never remove a cost or mark it free just to pass checks.
